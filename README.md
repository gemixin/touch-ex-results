# Touch-Ex-Results

This repository stores results from experiments conducted using the [Touch-Ex](https://github.com/gemixin/touch-ex) pipeline. It contains saved experiment metadata, evaluation outputs, plots, and notebooks for analysing completed experiments.

The experiments compare tactile image encoders and preprocessing configurations, then assess the selected approach across object recognition, object-region classification, and force-aware perception tasks.

## Project Structure

- `results/` contains experiment records, CSV tables, and plots, organised by experiment purpose and then task
- `notebooks/` contains notebooks for viewing and comparing saved experiments
- `exports/` contains additional plots and tables generated by notebooks

## Installation

Clone the repository:

```bash
git clone https://github.com/gemixin/touch-ex-results.git
cd touch-ex-results
```

Install the dependencies with pip:

```bash
python3 -m pip install -r requirements.txt
```

Or create the provided Conda environment:

```bash
conda env create -f environment.yml
conda activate touch-ex-results
```

## Results Format

Results are organised by experiment purpose and then task:

```text
results/<experiment_purpose>/<task>/
├── experiments.parquet
├── plots/<NNN>/
└── tables/<NNN>/
    ├── summary.csv
    └── <run_name>/classification_report_<split>.csv
```

| Task type | Task folder |
| :--- | :--- |
| Classification | `<target>_classification` |
| Force-conditioned classification | `<target>_conditioned_classification` |
| Regression | `<target>_regression` |

`<NNN>` is the zero-padded experiment number within each purpose/task combination. Each experiment contains one or more runs, representing individual models or configurations. Experiment names are recorded as metadata and do not determine output paths.

Each `experiments.parquet` file contains one row per run, including model and checkpoint information, data and training configurations, training history, predictions, and evaluation metrics.

Each experiment saves CSV tables under `tables/<NNN>/`:

- `summary.csv`: one row per run, with metrics for each scored evaluation split
- `<run_name>/classification_report_<split>.csv`: per-class precision, recall, F1, and support for each scored classification split (classification tasks only)

Plots are saved under `plots/<NNN>/`. Classification plots include training curves, confusion or prediction matrices, and comparisons between runs. When enabled, static and interactive t-SNE plots are generated for every evaluated classification split. 

Regression plots include training curves, predicted-versus-true values, and residuals.

### Metrics

| Task | Metrics |
| --- | --- |
| Classification | Accuracy and macro F1 |
| Regression | MAE, RMSE, and R² |

Metrics are calculated per frame. Accuracy is recorded as a percentage, while macro F1 is on a 0–1 scale and averages over the ground-truth classes present in each split. Regression errors are reported in the original target units: newtons for `force_n` and volts for `fsr_voltage`.

For object and object-region classification on `test_unseen_related`, the true identities have no corresponding training classes. Predictions are retained and displayed against the original source identities, but classification loss, accuracy, F1, and per-class reports are not calculated. Force-level classification and regression retain their usual metrics on this split.

## Evaluation Protocol

The source training split is partitioned approximately 70:15:15 into internal training, validation, and test partitions. Partitioning is performed by interaction, keeping all frames from an interaction together.

Dataset partitioning uses seed `129`, independently of the training seed, which defaults to `156`. The internal test partition is reserved first using `object_region` stratification and remains consistent across tasks for a fixed dataset and split size.

Experiments use two purposes:

| Purpose | Evaluated splits |
| --- | --- |
| `model_selection` | Internal `val` and `validation_unseen_matched` |
| `final_evaluation` | Internal `test`, `test_unseen_matched`, `test_unseen_related`, and `validation_unseen_matched*` |

*During final evaluation, `validation_unseen_matched` is  evaluated to provide additional insight into performance on the validation instances, but the results are not considered independent test results. 

Internal validation controls checkpoint selection and early stopping in both modes: accuracy for classification and normalised Huber loss for regression.

The internal test partition measures performance on new interactions from represented objects. The matched unseen test split measures generalisation to new physical instances of known object categories. The related unseen test split supports analysis of predictions on new but tactually related categories.

## Experiment Summaries

### Model and Configuration Selection

These experiments use `object_region` classification and are stored under:

```text
results/model_selection/object_region_classification/
```

Internal validation accuracy determines checkpoint selection and early stopping. Both internal validation accuracy and accuracy on `validation_unseen_matched` guide model and configuration selection.

Unless stated otherwise, the initial model comparisons use `pad_224`, background subtraction, dataset normalisation, and no training augmentation. Later sweeps retain settings selected in preceding stages, except those being varied. Complete data and training configurations are retained in each experiment record.

#### 001 — Frozen-backbone model comparison

Compare ResNet-18, ResNet-50, EfficientNet-B0, ViT-Small/16, and DeiT-Tiny with their pretrained backbones frozen. Only the classification heads are trained, using a learning rate of `2e-4`.

#### 002 — Fine-tuned model comparison

Compare the same five pretrained encoders through end-to-end fine-tuning, alongside the baseline CNN trained from scratch. Pretrained models use a learning rate of `2e-5`; the baseline uses `3e-4`.

#### 003 — Frozen T3-Tiny

Evaluate T3-Tiny with its pretrained encoder frozen, using `center_crop_224`, dataset normalisation, and no background subtraction. Only the classification head is trained, using a learning rate of `2e-4`.

#### 004 — Fine-tuned T3-Tiny

Evaluate T3-Tiny through end-to-end fine-tuning using `center_crop_224`, dataset normalisation, and no background subtraction. The learning rate is `2e-5`.

#### 005, 006 — Candidate learning-rate sweep

Compare learning rates of `1e-5`, `2e-5`, `3e-5`, and `4e-5` for the two selected candidate encoders (ViT-Small/16 and ResNet-18) identified by the preceding comparisons.

The selected encoder and learning rate (ResNet-18 and `3e-5`) is retained for subsequent experiments.

#### 007 — Weight-decay sweep

Compare weight decay values of `0.0`, `0.002`, `0.02`, and `0.1`.

The selected weight decay (`0.1`) is retained for subsequent experiments.

#### 008 — Background-subtraction and normalisation sweep

Compare all six combinations of:

- Background subtraction enabled or disabled
- No normalisation, dataset normalisation, or ImageNet normalisation

The selected background-subtraction (enabled) and normalisation settings (dataset) are retained for subsequent experiments.

#### 009 — Augmentation sweep

Using the selected model and configuration, compare four training augmentation settings:

- No augmentation
- Colour jitter
- Horizontal flipping
- Colour jitter and horizontal flipping

The selected augmentation settings (colour jitter and horizontal flipping) complete the final training recipe.

### Final Evaluation

The selected backbone and recipe are applied independently to each final task. Each task starts from the same pretrained encoder checkpoint and is fine-tuned with its own task-specific head, producing separate encoder weights.

Each final task is trained and evaluated three times, using training seeds `156`, `157`, and `158`. Dataset partitioning remains fixed at seed `129` across these runs.

Experiment numbering starts independently within each task directory under `results/final_evaluation/`.

| Task folder | Experiments | Summary |
| --- | --- | --- |
| `object_classification` | `001-003` | Object classification |
| `object_region_classification` | `001-003` | Object-region classification |
| `force_level_classification` | `001-003` | Force-level classification |
| `object_conditioned_classification` | `001-003` | Object classification with ground-truth force level supplied as an additional input |
| `object_region_conditioned_classification` | `001-003` | Object-region classification with ground-truth force level supplied as an additional input |
| `force_n_regression` | `001-003` | Continuous force prediction in newtons |
| `fsr_voltage_regression` | `001-003` | FSR output voltage prediction in volts |

Conditioned classification combines the image representation with a normalised force-level scalar through a fusion layer. These experiments are compared with their corresponding image-only classification results.

Regression uses a single-value prediction head and Huber loss, with targets normalised using training-partition statistics. MAE and RMSE are reported in the original target units.
